// TUG2-specific gamedata, kept separate from insurgency.games.txt so that file can stay a verbatim
// copy of its upstream source.
//
// These are all NextBot AI internals used by gg2_bot_smoke_suppress. They are resolved by mangled
// symbol name (the "@" prefix), NOT by byte signature. That works because the Linux server binary
// ships its full symbol table: server_srv.so exports only 7 entries in .dynsym, but .symtab holds
// ~46,500, and SourceMod's symbol resolver reads .symtab for non-stripped libraries. The existing
// insurgency.games.txt relies on the same behaviour (e.g. ForceRespawn, which bm2_respawn calls in
// production, is likewise .symtab-only).
//
// There are no "windows" keys because there is no Windows build of this server, and a mangled
// Itanium-ABI name would be meaningless there anyway - it would need a real byte signature.

			// THE suppression gate. Disassembly shows CINSBotSuppressTarget - the action that makes
			// a bot fire at a position rather than a visible target - is constructed in exactly two

			// The two guards that sit immediately before the ShouldSuppressThreat call inside
			// CINSBotCombat::Update. Read out of the disassembly:
			//
			//   call *0x38(%eax)   -> IsVisibleInFOVNow()        ; TRUE  -> skip suppression
			//   call *0x30(%eax)   -> GetTimeSinceBecameKnown()  ; < threshold -> skip suppression
			//
			// The second is why this never fired. We inject the threat fresh and then re-seed it
			// every sweep, so "time since became known" sits at ~0 forever and never ages past the
			// threshold - our own seeding was defeating the gate. Forcing a large value clears it
			// regardless of the (PIC-relative, hard to read) constant it is compared against.
			// The real gate behind the per-smoke dropouts. CINSBotCombat::Update does:
			//   706b2c: call GetActiveWeaponAmmoRatio ; 706b3d: fstps -0x3d8(%ebp)
			//   706c55: movss 0.1 ; comiss -0x3d8(%ebp) ; 706c64: jbe <suppression path>
			// Below a 10% ammo ratio the bot never reaches the suppression path at all - not the
			// age gate, not the weapon-class gate, not ShouldSuppressThreat.
			// The engine's own weapon selection. A bot that ran dry falls back to a pistol and
			// then to its knife, and nothing re-runs selection once ammo is restored - so it sits
			// on a knife holding full magazines, and melee can never pass the suppression gate.
			// Measured live: 7 of 25 bots on knives, 6 on pistols, only 7 still eligible.
